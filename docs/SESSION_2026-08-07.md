## §1 TestSuite-Migration: Konflikte & Lösungen

### Ausgangslage
- 37 Test-Suiten nutzten noch `AssertTrue`/`AssertFalse`/`AssertEqual`/`AssertNull`/`AssertNotNull`-Helper + `_passed`/`_failed`-Zähler
- `scripts/migrate_to_tscheck.py` existierte als untracked Script (155 Zeilen), aber der `origin/test-migration-complete`-Branch war kaputt (Orphan-Commit, Kompilierfehler)
- ~43 Dateien im Hybrid-Zustand: einige `ts.Check()`-Calls, aber noch alte Helper

### Konflikt #1: Orphan-Commit auf `test-migration-complete`
**Symptom:** `aadb455` hatte keinen Parent, `git merge --allow-unrelated-histories` produzierte 50+ add/add-Konflikte.
**Root Cause:** Der Branch wurde via `git commit-tree` oder ähnlich ohne Parent erstellt.
**Lösung:** `git cherry-pick aadb455` → Migration-Script aus dem Commit extrahiert, Branch gelöscht, Migration neu ausgeführt.

### Konflikt #2: Regex matched Helper-Definitionen
**Symptom:** `private static void AssertTrue(bool condition, string label)` wurde zu `private static void ts.Check(bool condition, string label)`.
**Root Cause:** Die Call-Site-Regex `AssertTrue\s*\((.+?),` matchte auch Methodensignaturen.
**Lösung:** Schritt-Reihenfolge getauscht: erst `_remove_helpers()` (brace-counting), dann `_replace_calls()`.

### Konflikt #3: Greedy `.` matchte über mehrere Statements
**Symptom:** Erste `AssertTrue(` im File matchte alles bis zur letzten Helper-Definition (500+ Zeilen).
**Root Cause:** `.+` mit DOTALL war zu gierig, backtracking fand Match in `Log.Error("...", "got " + actual)`.
**Lösung:** `[^;]+` statt `.+` für Condition-Args — Semikolon als Statement-Grenze.

### Konflikt #4: Non-greedy `[^;]+?` stoppte an erstem Komma
**Symptom:** `AssertFalse(HasCapabilityOrWarn(packageId, capabilityId, 1, "Test"), "label")` → Condition wurde zu `HasCapabilityOrWarn(packageId`.
**Root Cause:** `[^;]+?` (non-greedy) nahm minimal Match bis zum ersten `,`.
**Lösung:** `[^;]+` (greedy) — matcht maximal ohne Semikolon-Überschreitung.

### Konflikt #5: Labels mit `)` in String-Literalen
**Symptom:** `"Set: 3 distinct entries), no duplicates collapsed"` — `)` in String brach Regex-Paren-Matching.
**Root Cause:** `_find_matching_paren` und `_split_args` ignorierten String-Literal-Context.
**Lösung:** String-Awareness in Paren-Counter: tracke `"` und `'` Zustände, überspringe Escapes.

### Konflikt #6: `AssertEqual`-Regex captured Komma im ersten Arg
**Symptom:** `AssertEqual(18, CharacterSetup.FixedBiologicalAge, "label")` → `[^;]+` für erstes Arg matchte `18, CharacterSetup.FixedBiologicalAge`.
**Root Cause:** `[^;]+` exkludiert keine Kommas.
**Lösung:** Erstes Arg auf `[^;,]+` (keine Semikolons, keine Kommas). Zweites Arg ebenfalls.

### Finale Lösung: Paren-Counting-basierter Parser
Nach 6 Regex-Iterationen kompletter Rewrite zu token-basiertem Ansatz:
- `_find_matching_paren()`: String-aware Klammerzähler
- `_split_args()`: Komma-Split nur auf Depth 0, String-Context respektiert
- `_replace_calls_paren()`: Findet `AssertXxx(`, matched `)`, extrahiert Args, baut `ts.Check(...)`.

**Ergebnis:** 37 Dateien, +888/-1604 Zeilen (−44% Boilerplate). Build: ✅ 5/5. Gate: 2694 passed, 0 failed.

## §2 Parser-Lücken nach Migration

### Lücke #1: `TEST-FAIL` nicht erkannt
**Symptom:** `RX_TEST_FAILED` suchte `test FAILED:` (Leerzeichen), aber `TestSuite.Check()` schreibt `TEST-FAIL` (Bindestrich).
**Fix:** Regex erweitert: `(?:test FAILED:?|TEST-FAIL)\s*(.+)`.

### Lücke #2: Doppelte Suite-Summaries
**Symptom:** Jede migrierte Suite emittiert ZWEI Summary-Lines:
- Legacy: `"Suite tests: 0 passed, 0 failed."` (`_passed`/`_failed` sind tot, immer 0)
- TestSuite: `"Suite: 6 passed, 0 failed (min=1)."` (echte Werte)
**Fix:** Dedup in `parse_player_log()`: pro `(package, suite_name)`-Key nur den Eintrag mit höchstem `passed+failed` behalten.

### Verbleibend
- ~68 statt ~44 Suiten im Parser-Output (Name-Mismatch Legacy↔TestSuite bei wenigen Suiten)
- 2 Suiten zeigen 0/0 (RimconemyStartState, RimconemyUnlockExtension) — Legacy-Maske
- Kosmetisch, keine funktionale Lücke. `runtime_test.sh` prüft gegen Raw-Log (SSOT).

## §3 Live Monitor (`scripts/live_monitor.py`)

### Design
- **File-Tailing:** `time.sleep(0.5)` Poll-Loop, File-Position-Tracking, Log-Rotation-Erkennung
- **Noise-Filter:** Nur `[Rimconemy.*]`-Lines + kritische Vanilla-Fehler (NullRef, XML error, Cross-Ref)
- **Unterdrückt:** UnityEngine-Fallback, UnloadTime, Worker-Thread-Spam
- **Dashboard:** Alle 2s `\033[2J\033[H` Clear+Redraw, Box-Drawing-Charaktere
- **Farben:** Grün=PASS, Rot=FAIL/ERROR, Gelb=WARN, Cyan=Info, Magenta=Cross-Ref
- **Anomalien:** Vanilla-Criticals in separatem Bucket

### Modi
```
python3 scripts/live_monitor.py              # Live-Tail (startet am Dateiende)
python3 scripts/live_monitor.py --once        # Einmaliger Parse + Dashboard
python3 scripts/live_monitor.py --cold        # Komplettes Log ab Anfang
python3 scripts/live_monitor.py --level 3     # Debug: alle Zeilen
```

### Edge Cases
- **Log-Rotation:** RimWorld löscht/ersetzt Player.log → erkannt via `size < position`, Reset auf 0
- **TTY-Erkennung:** `sys.stdout.isatty()` — Farben nur im Terminal
- **Dedup:** Legacy 0/0-Summaries werden nicht angezeigt (`total > 0`-Guard)
